# 报告撰写 Skill

## 目标

把模板初稿和结构化数据整理成一份可以直接发出去的周报 / 日报 / 月报：

- 覆盖看板里出现的所有项目与任务，不能漏项；
- 保留所有项目名、任务名、日期、时长、优先级、截止日期等事实；
- 对用户写得很短的「阶段成果 / 下一目标」做适度扩写，让句子完整、有上下文，但不要编造具体客户、技术栈、指标或成果；
- 整体长度接近调用方给出的「目标总字数」，允许 ±20%；
- 语气简洁、专业、书面化，不口语化，不使用第一人称。

## 允许的扩写

用户经常只写「修 bug」「联调」「写文档」这类很短的记录。你可以结合：

- 项目名、任务名；
- 阶段成果、下一目标；
- 优先级、截止日期、任务状态；
- 同一任务前后的阶段记录；
- 自定义字段（如客户、标签、模块等）；

把一句话扩展成 1–2 句完整表述，例如：

- 「修 bug」→「围绕【任务名】定位并修复阶段内问题，推进任务交付。」
- 「联调」→「完成【任务名】的接口联调与问题排查，为后续验收做准备。」
- 「写文档」→「整理【任务名】的阶段产出并补充说明文档。」

但不得编造：

- 具体数字、金额、百分比、客户名、人名；
- 具体技术栈、框架、服务器配置；
- 输入中不存在的结论、评价、风险或承诺；
- 新的项目 / 任务 / 阶段条目。

如果记录里出现「（未填写成果）」或「（未填写计划）」，根据项目、任务和上下文改写成概括性表述，不要保留占位符。

## 结构

- 保留报告标题与「工作成果 / 工作计划」两个大章节；
- 章节内可以用短段落或项目符号，不需要逐条照抄模板句式；
- 同一任务的多条阶段记录可以合并成一段，但项目名和任务名必须保留；
- 可以调整条目顺序，让内容更连贯，但不得删除任何项目 / 任务；
- 计划部分只写输入中已有的下一步目标，可做措辞扩写，不写成承诺或具体时间点。

## 不要写单个任务耗时

报告中不要出现“某任务花了多少时间 / 多少分钟”这类逐任务耗时；周期总时长可以保留。任务耗时只用于你判断工作量和篇幅，不要写进正文。

## 长度

以调用方给出的「目标总字数」为准：内容太少时，优先补充上下文和衔接；内容太多时，压缩重复表达，但保留所有项目 / 任务与关键事实。

## 输出

只输出报告正文，不要输出「以下是改写后的报告」、解释、Markdown 代码围栏或额外建议。
