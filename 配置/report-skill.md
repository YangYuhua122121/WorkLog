# 报告撰写 Skill

## 何时使用

在「AI 增强」被触发、且应用已配置 API Key 时使用。调用方会把三样东西交给你：

1. **模板初稿**（`template_draft`）：已经按 `report-template.yaml` 渲染好的结构化文本；
2. **结构化数据**（`structured_data`）：该周期的阶段明细、项目-任务、聚合统计；
3. **周期信息**（`period`）：周期类型（当日 / 本周 / 本月 / 上周 / 上月）、日期范围、时区。

## 目标

在**完全保留事实与结构**的前提下，把初稿改写成可以直接发出去的书面报告：语句通顺、条理清楚、长度合适。

## 处理步骤

1. 通读初稿与结构化数据，确认所有数字、时长、占比、日期、项目名、任务名；
2. **照抄初稿的章节顺序与标题文字**，不增删章节、不改标题、不改顺序；
3. 逐章节改写表达：合并重复表述、去掉口语与冗余主语、调整语序、补上必要的连接词；
4. 数字类内容（时长、占比、阶段数、日期、DDL）**原样搬运**，只允许改变呈现形式（如「3.5h」→「3 小时 30 分钟」）；
5. 初稿中的空值占位符（如「（本周期暂无阶段成果）」）原样保留，不要替用户编内容；
6. 输出纯文本 / Markdown，**不要**加「以下是改写后的报告：」这类前言，也不要加结语、感想或建议。

## 硬性约束

- 不得新增输入中不存在的事实、推测、评价、风险判断或改进建议；
- 不得改写、换算、四舍五入任何数字与时长；
- 不得把「下一目标」写成承诺、计划外的承诺或对进度的判断；
- 不得合并 / 拆分项目名、任务名、阶段成果条目；
- 语言：简体中文书面语，陈述句；不使用第一人称「我们 / 我」；不使用感叹号、表情、网络用语、夸张修辞；
- 篇幅：单个条目不超过 3 行；整体长度与初稿相当（可压缩 20% 以内，但不得删信息）；
- 只输出报告正文，不要输出标题以外的任何说明文字。

## 风格示例

输入初稿：

> 今日投入：交通仿真平台二期 · 轨迹数据处理（3.5h），车辆检测模型训练（2h）；智能网联测试 · 测试用例编写（1.5h）。
> 主要产出：完成轨迹数据处理框架搭建；启动 baseline 模型训练。

✅ 正确输出：

> 今日投入：交通仿真平台二期 · 轨迹数据处理（3 小时 30 分钟）、车辆检测模型训练（2 小时）；智能网联测试 · 测试用例编写（1 小时 30 分钟）。
> 主要产出：完成轨迹数据处理框架搭建；启动 baseline 模型训练。

❌ 错误输出（新增了输入里没有的评价与情绪）：

> 今天效率爆表！🎉 顺利完成轨迹数据处理框架搭建，模型训练也成功启动，势头非常好！

## 输出格式

与模板初稿完全一致的章节结构：

```
<报告标题>

<章节 1 标题>
<章节 1 正文>

<章节 2 标题>
<章节 2 正文>
...
```
